# gakumas-engine との比較（2026-10-04）

比較元は [gakumas-tools/gakumas-tools の packages/gakumas-engine](https://github.com/gakumas-tools/gakumas-tools/tree/58c7148cb1d097b78f66faa4a9ab6d5212f083b7/packages/gakumas-engine)、コミット `58c7148cb1d097b78f66faa4a9ab6d5212f083b7`。
CardManager、Executor / resolvers、EffectManager、BuffManager、TurnManager、StageEngine、Evaluator、設定・定数・乱数処理を現在の実装と照合した。
修正の基準は `gakumas_analysis_fullcfg.elf` の ARM64 IL2CPP 実装。参照エンジンと異なる処理をそのまま移植する方法は採っていない。
ELF アーカイブのハッシュは [elf-parity-status.md](elf-parity-status.md) に記録している。

## 追加・修正した処理

| 対象 | 比較で確認した欠け | 修正と回帰テスト | ELF の根拠（RVA） |
| --- | --- | --- | --- |
| カードの移動時効果 | マスターの移動時効果を試験カードへ引き継いでいない | 効果・条件の配列を保持し、実際の移動先で発動。カードごとにターン内1回。条件不成立では回数を消費せず、保存・復元後も制限を保持 | `InsertMoveEffect` `0x8069024`、手札 `0x8068CC4`、プール `0x8068970`、使用フラグ `0x822A72C` |
| 保留枚数上限 | `holdLimit` を保持するだけで上限処理がない | 既存の古い保留を捨て札へ移動。入力枚数自体が上限を超える場合は入力の先頭を直接捨て札へ送り、末尾を保留。保留に入らなかったカードの保留時効果は発動しない | `MoveCard` `0x82300A4`、上限分岐 `0x8231510`、既存カードの先頭取得 `0x823195C`、入力超過分 `0x8231A44` |
| 全力開始時の保留復帰 | 復帰処理がない | 通常のドロー後、保留の先頭から手札の空き枠に収まる最大2枚を戻す。通常ターンでは残す。これは参照エンジンの `pop()` による末尾取得とは異なる | 全力判定 `0x8097308`、空き枠と2の最小値 `0x80973BC`、保留 `Take` `0x80973EC`、手札移動 `0x80974C8` |
| 成長した参照スコア | 全力値参照などの効果に、固定値・攻撃回数の成長が適用されない | ネイティブの固定値対象と回数対象を区別。「エキスパート」で保留した「グランドフィナーレ」の成長・強制使用が55点×2回＝110点になる条件を検証 | `GrowEffectAffectProduceCardEffectList` `0x7FF2BF0`、固定値対象 `0x6905458`、攻撃回数対象 `0x6905720`、全力値参照 `0x8014618` |
| ドロー・移動の発動時点 | ドローをターン開始後の一括通知へ割り当て、手札・捨て札移動の通知がない | 個々のドロー・手札移動・捨て札移動を通知。直接生成による手札移動はドローと区別。手札上限で山札へ送ったカードは手札移動を通知しない | `IsDrawCardTrigger` `0x7FF7A10`、`IsMoveCardTrigger` `0x7FF7DF4`、結果通知 `0x80647DC` |
| 強気からの指針変更 | 退出条件が通知へ接続されていない | 指針の数値の増減と退出を区別。強気→全力は数値が増えても退出条件を判定。全力解除も確認 | 結果トリガー収集 `0x80647DC` |
| 同じカード内の複数変化 | 発動済み集合をカード全体で共有し、2回目の体力減少を抑制 | 個々の効果の変化ごとに判定。同一変化の複数フィールドでは重複を抑える。「初声の証・咲季」で体力2回減少→好印象4を確認 | 結果トリガー収集 `0x80647DC`、効果差分記録 `0x8061AA0` |
| 入れ子の効果差分 | 子の効果を実行した親も、その変化を再通知する | 子が実行した変化で親の比較基準を更新。検索数に応じた連鎖でも2回の減少が2回だけ発動する。使用中カードの検索数も参照できるよう修正 | 結果コマンド単位の通知 `0x80647DC` |
| Pアイテム・ギミックの効果の連鎖 | 発動元を問わず状態変化・移動のトリガーを起動する | Pアイテム自身・ギミック自身が実行したダメージによる結果トリガーを抑制。強制使用されたカードやカード自身の移動時効果はカードの実行元を持つ | `IsEnchantTriggerActive` `0x7FE4EDC` |

移動時効果がある実マスターは5種類・8バリエーション。
「輝きの到達点」「理想に手が届く日まで」（強化0〜3）「スーパーノヴァ」「グランドフィナーレ」「エキスパート」を、マスター `75eb2a94eb494a6e74053c0f295cb026e837e32a` から取得したフィクスチャで確認する。
通常の使用条件と移動時効果の条件は別々に判定する。

テストは [test_engine_comparison.mjs](../tests/test_engine_comparison.mjs)、マスター抽出は [build_engine_comparison_fixture.mjs](../tools/build_engine_comparison_fixture.mjs)。
実カードの効果を検証するケースと、発動時点をスコアの目印で切り分けるケースを区別している。

## 既存の対応と参照エンジンとの差

| 領域 | 現在の状態 |
| --- | --- |
| ターン内使用回数・直前カード分類 | PR #75の先行修正を維持。実Pアイテム・ドル道10グループ・アクティブ33行／メンタル50行の回帰テストがある |
| スコア計算・乱数 | float32の丸め、XorShift、カード検索の乱数消費を使用。参照エンジンの浮動小数点処理・乱数を置き換えに使わない。全ステージの初期化経路は未検証 |
| 全力の解除 | ネイティブのカード使用後の解除・全力値消費を維持。参照エンジンのターン終了を基準とした処理は移植していない |
| カード成長・カスタマイズ・一時強化・アンコール・強制使用 | 既存処理を維持し、今回の移動時成長との組み合わせを追加検証。全種類の組み合わせの実機一致は未検証 |
| Pアイテム・予約・有限ターン状態 | 基本の発動、共有回数、予約、ターン消費は既存対応。新規付与の消費時点、予約を含む全順序は横断照合が必要 |
| Link Contestの区間交代 | 未実装。参照エンジンの `StageEngine.changeIdol` / `CardManager.changeIdol` に相当する入力・実行経路がない。ネイティブ `ChangeIdol` `0x805E59C` は体力・メイン効果・カードプールを変更する。各区間のデッキ・体力・アイドル情報、カードプールと継続状態の引き継ぎ、開始時効果を一体で接続する必要がある |
| AI・評価関数 | 参照エンジンの選択規則とこちらの探索・評価方法は別実装。選択方針の差をゲーム本体の仕様差として扱わない |

## 残る検証境界

全ステージの初期乱数消費、複数のPアイテム・予約・ギミックが同時発動する場合の収集と実行の全順序、強制使用時の全使用条件、新規状態の最初のターン消費、エンチャントUIDと `PlayingEnchantIsTriggerActive` の伝搬は未検証。
今回の実行元制限はPアイテム・ギミックを対象とし、予約を含むエンチャントの全フラグを再現したという意味ではない。

実機の全行動・中間状態・各攻撃のログとの比較はまだない。
効果2,098件、Pアイテム478件、カード1,732バリエーションの実行スモークテストで未対応エラーが0件でも、全ロジック・全ステージの完成は主張しない。
