# シミュレーションの途中経過バックアップ

試験とドル道のシミュレーション画面に「途中経過をJSON保存」「途中経過を復元」を用意する。終了済みターンだけでなく、現在のターンの途中状態も保存できる。

| JSON項目 | 内容 |
| --- | --- |
| `format`, `version`, `mode` | `gakumas-sim-progress`、2（旧版1も読込可能）、`exam`または`tower` |
| `seed`, `currentTurn` | 開始Seedと現在のターン |
| `turns[].attribute`, `multiplierPercent` | 属性とステージ倍率。3694%は3694として保存。倍率未設定はnull |
| `turns[].handAdded` | そのターンに手札へ入ったカード。重複を保持し、カードID・強化段階・インスタンスtoken・到着順を記録 |
| `turns[].usedCards` | 使用したカードと順番。強制使用の有無も記録 |
| `turns[].events` | 発動順の詳細イベント。カード、Pアイテム、継続効果、ギミック、ドリンク、進行処理の発動元を区別 |
| `events[].changes` | 状態名、変更前、変更後、数値の場合は差分 |
| `events[].moves` | カード生成・移動先・移動元 |
| `checkpoint` | 乱数、全カード領域、発動回数、継続効果、現在ターン、内部Map/Setを含む再開可能な状態 |
| `catalogs` | 再開に必要な解決済みマスター。保存後のマスター更新で処理結果が変わることを防ぐ |

履歴は新規シミュレーションから記録する。以前のlocalStorage状態に詳細履歴がない場合は、そのことを表示する。過去の詳細値を推測して埋めない。

カードの値変更にPアイテムが反応する場合、親の変更を先に記録し、Pアイテムの変更を別イベントとして記録する。子の差分を親の差分へ二重計上しない。一手戻ると詳細履歴も戻る。AIの探索状態では履歴記録を無効にし、探索中の仮想操作を実際の履歴に混ぜない。

JSONの状態値はエンジンの単位を保持する（permilは1000分率、倍率フィールドは倍率）。画面では対応する割合を%表示する。非有限数はJSONの型付き表現で保存する。これは実機の履歴そのものの取り込みではなく、シミュレータの処理履歴である。

## 私を超えての修正

マスター `vertesan/gakumasu-diff@32e80387586d7a1322b6ebc0f3e27ced1564416c` を使った回帰テストを保存している。

- `ExamPlayableValueAdd` の増加量は `effectCount`。`effectValue1` は0であり、増加量に使わない。
- カードの `effectGroupIds` をYAMLから保持し、元気カードの検索・使用回数判定を可能にする。
- カード効果の説明は実行時と同じ効果マスターを優先する。継続効果の説明文はマスターから取得し、古いID専用解析による「未対応」の誤表示を防ぐ。
- 全強化段階で追加使用、ターンを跨ぐ元気カード2回判定、私を超えて（翔）の山札先頭生成、その使用時の追加使用とドローを検証する。

実機との全効果・全発動順の一致を保証するものではない。今回の回帰テストは、実マスターの対象条件と値、保存・復元後の処理一致を検証する。

## 容量削減とドル道26階の回帰検証

バージョン2では編成とチェックポイントから参照を辿り、必要なマスターのみ保存する。将来生成されるカード、全強化段階、カスタマイズ、成長効果、継続効果、検索、ランダムプール、連鎖効果も含める。検索条件で全カタログから生成する場合は、その条件に合う候補を元の順序で保持する。マスター更新後でも同じ候補と乱数消費を維持する。詳細履歴は `turns` に一度だけ保存し、読み込み時に実行状態の履歴を復元する。JSONの不要な空白も削除する。

提供された2ターン目のJSONは11,424,013バイトだった。旧JSONの状態を変えずにバージョン2で再保存すると483,739バイト（約96%削減）。旧版は保存時点の計算結果も含めて読み込むため、過去の誤発動やドロー結果を訂正するには新規シミュレーションからやり直す。

ELFから確認した修正：

- `IsFieldStatusTriggerStatusEffect` の RemainingTurn は `残りターン <= 設定値`。現在ターンを含めて数える。
- `StartPlay` はドロー後の開始タイミング。頂点の輝きの `phaseValues: [0]` をターン番号と比較しない。16ターン試験では16・17ターン目に各1回発動し、18ターンまで延長する。
- `DebuffRecoverEffectExecutor` は低下状態をUid降順で選択する。状態付与順をプール横断で記録し、最新の状態から解除する。紫ライトの最後の付与は手札減少なので、2ターン目の応援でこれを解除してから3枚引く。
- 使用可能回数を使い切って終了したターンは、ターンスキップ条件を発火させない。

ターン属性順の不一致は、山札シャッフルより前のNPCスコア生成による乱数消費を含めていなかったことが原因。ELFではドル道のExamTypeは5で、属性生成の後にNPCの各ターンのスコアを生成する。属性生成 `ターン数 - 3` 回とNPC生成 `ターン数 × NPC人数` 回を山札のSeedから戻し、属性生成の開始状態を復元する。NPC人数は選択した階層のマスターから取得する。

16ターン・NPC5人では93回戻す。`3437998083` は変更せず、属性生成だけを `775645918` から行うと最初の2ターンがビジュアル→ビジュアルとなり、1ターン目の好印象スコアも259になる。全スキップ時の山札・ドロー・リサイクルの乱数状態は変えない。プレビューと実行には同じ変換を使い、チェックポイントの `turnInitialization` に使用した開始状態と消費回数を保存する。旧バックアップの過去の計算結果はそのまま復元するため、修正を反映するには同じSeedで新規シミュレーションを開始する。

カード効果による強化は未強化カードの無印→+のみ。既に+のカードはそのままにする。通常試験のサポートカードによる一時強化は別経路。継続効果名は付与元カードの実際の名称・強化段階を保存して表示する。過去に誤って++にしたカードや、それによって余分に生成したカードは既存チェックポイントから勝手に削除しない。該当するバックアップは同じSeedで最初から操作を再実行する。


## 初回付与ターンの期間と直接効果

`ExamStatusEffectBase.IsPassingTurnStart` (0x80215A0) は、新規ステータスがターン開始を通過したかを保持する。`ExamLoopTaskAsync` の 0x8070394 はドロー後・StartPlay 前にステータスをマークする。`SpendTurn` 共通処理 (0x90FC418) は未通過のステータスを減らさない。好印象・好調・絶好調、有限ターンの強化、継続効果にもこの期間管理を適用する。既存ステータスへの追加付与はフラグを維持する (`AddTurn`: 0x8021774)。

使用数追加 (`PlayableValueAddStatusEffect`, 0x802C858) は `CardPlayCountAdd` (0x7FF0638) で既存の追加数を先に1消費する。追加数が無い場合だけ `IsTurnCardPlayEnd` を立てる。さらに `AddPlayableValueAdd` (0x7FF195C) は、すでに `IsTurnCardPlayEnd` の状態で追加数を付与した場合、ターンを再開して `UsePlayableValueAddCount` (0x802C99C) を即1回実行する。したがって通常の1回を使い切った後に得た `+1` は、そのターンを再開するために即消費され、スキップしても次ターンへ `+1` は持ち越さない。

通常の継続効果による好印象増加は、「直接効果で好印象が増加後」の条件を満たさない。`IsEnchantTriggerActive` (0x7FE4EDC) と `IsEnchantTriggerActiveEffectType` (0x6905888) に従い、通常の継続効果から結果トリガーを連鎖させない。強制カード使用はカードの直接効果として処理する。

バックアップはカスタマイズ段階の入れ子 `Map` も保存する。以前のJSONで `{}` になった段階表は復元できない。修正前に終了したターンの結果も遡及変更しないため、比較は試験開始から再実行する。

好印象の自然減少も累計消費に含む (`ReviewStatusEffect.SpendTurn`: 0x803C158 → `AddReviewConsumptionSumCount`: 0x804C80C)。これは「先へ進む姿」の好印象増加量に影響する。参照式による好印象増加も、結果の状態差分として直接効果条件を満たす (`ReviewDependReviewConsumptionSumEffectExecutor`: 0x801A100)。通常の継続効果からの連鎖とは区別する。

`CostReviewReduce` などのカスタムは効果種別自体がコスト種別を指定する。マスターの `costType: ExamCostType_Unknown` でも適用する。以前の保存データに残った未適用の効果はインポート時に一度補正する。入れ子Map保存と併せ、カスタマイズを保った再実行を可能にする。過去ターンのステータス配列も独立したコピーを保存し、後の追加付与で履歴を書き換えない。

提供された記録を同じシード・カード順で開始から再実行し、通常16ターンの開始手札と全19ターンの終了スコアを照合した。終了スコアは全ターン一致し、最終値も実機と同じ662,831Pt。8ターン目の実機ログにある各スコア変化 (3,067→3,149→3,414→3,679→3,964→4,758) も一致する。この実例の一致を、全ステージ・全カードの実機一致とは扱わない。
