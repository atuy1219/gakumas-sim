# シミュレーションの途中経過バックアップ

試験とドル道のシミュレーション画面に「途中経過をJSON保存」「途中経過を復元」を用意する。終了済みターンだけでなく、現在のターンの途中状態も保存できる。

| JSON項目 | 内容 |
| --- | --- |
| `format`, `version`, `mode` | `gakumas-sim-progress`、1、`exam`または`tower` |
| `seed`, `currentTurn` | 開始Seedと現在のターン |
| `turns[].attribute`, `multiplierPercent` | 属性とステージ倍率。3694%は3694として保存。倍率未設定はnull |
| `turns[].handAdded` | そのターンに手札へ入ったカード。重複を保持し、カードID・強化段階・インスタンスtoken・到着順を記録 |
| `turns[].usedCards` | 使用したカードと順番。強制使用の有無も記録 |
| `turns[].events` | 発動順の詳細イベント。カード、Pアイテム、継続効果、ギミック、ドリンク、進行処理の発動元を区別 |
| `events[].changes` | 状態名、変更前、変更後、数値の場合は差分 |
| `events[].moves` | カード生成・移動先・移動元 |
| `checkpoint` | 乱数、全カード領域、発動回数、継続効果、現在ターン、内部Map/Setを含む再開可能な状態 |
| `catalogs` | 再開に必要な解決済みマスター。保存後のマスター更新で処理結果が変わることを防ぐ |

履歴は新規シミュレーションから記録する。以前のlocalStorage状態に詳細履歴がない場合は、そのことを表示する。過去の詳細値を推測して埋めない。

カードの値変更にPアイテムが反応する場合、親の変更を先に記録し、Pアイテムの変更を別イベントとして記録する。子の差分を親の差分へ二重計上しない。一手戻ると詳細履歴も戻る。AIの探索状態では履歴記録を無効にし、探索中の仮想操作を実際の履歴に混ぜない。

JSONの状態値はエンジンの単位を保持する（permilは1000分率、倍率フィールドは倍率）。画面では対応する割合を%表示する。非有限数はJSONの型付き表現で保存する。これは実機の履歴そのものの取り込みではなく、シミュレータの処理履歴である。

## 私を超えての修正

マスター `vertesan/gakumasu-diff@32e80387586d7a1322b6ebc0f3e27ced1564416c` を使った回帰テストを保存している。

- `ExamPlayableValueAdd` の増加量は `effectCount`。`effectValue1` は0であり、増加量に使わない。
- カードの `effectGroupIds` をYAMLから保持し、元気カードの検索・使用回数判定を可能にする。
- カード効果の説明は実行時と同じ効果マスターを優先する。継続効果の説明文はマスターから取得し、古いID専用解析による「未対応」の誤表示を防ぐ。
- 全強化段階で追加使用、ターンを跨ぐ元気カード2回判定、私を超えて（翔）の山札先頭生成、その使用時の追加使用とドローを検証する。

実機との全効果・全発動順の一致を保証するものではない。今回の回帰テストは、実マスターの対象条件と値、保存・復元後の処理一致を検証する。
