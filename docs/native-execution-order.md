# 実機IL2CPPの発動予約・実行順序・乱数消費（ELF v31）

対象: `gakumas_analysis(1).elf` / Build ID `77fda4e2a21f23954e2349b83fc113ede408f70b`
（RVAはこのBuild ID専用。別バージョンでそのまま使用しない）。

## このPRで機械語から確認して変更した点

### 1. 発動予約の回数は効果の実行より前に消費

`ExamSequence.GetInsertTriggerEffectListCommand @ 0x80A7C18` 内で
`TriggerEffectStatusEffect.SpendCount @ 0x8084E54` への直接 `BL` が
`0x80A8104` に存在する。

発動条件を一括評価し、登録済みのコマンドと発動回数の予約を確定してから
各 `ExecuteEffect` を実行する。以前のスケジューラーは登録ごとに
「効果実行→SpendCount」を交互に実行していたため、
入れ子の状態変化からまだ消費していないカウンタが見えていた。

`web/native_effect_scheduler.js` を次の2段階にした。

1. 優先度・登録順に発動条件の候補をスナップショットし、
   回数・共有上限を予約して **全件消費**。未実装のフェーズは従来通り明示的に未対応。
2. 予約済みの効果を同じ優先順で実行。
   ネストした通知や発動回数依存の計算は予約済みの最新上限を参照する。

発動直後の共有カウンタを更新する既存 `afterRegistration` フックは、
内部的には登録時点の「予約確定処理」として効果実行より前に呼ぶ
（API名は互換性維持のため残す）。

### 2. XorShift32: ネイティブの戻り値と更新順を再現

実機 `ExamParameterModel.GetRandomInt()`（`0x808A340`）:
先に `_random`（オフセット`0x77C`）を読み、符号ビットを反転した
`Int32` を返し、`13,17,5` のXorShift32で次状態を書き込む。

実機 `GetRandomInt(int min, int max)`（`0x808A438`）:
`sub w10, w2, w1` で幅を計算し、`umull`→上位32bitで整数写像し、
次の状態を `str w10,[x8,#0x77c]` へ保存する。
**幅が0の場合も条件分岐でスキップせず、次状態を保存する。**

JavaScriptの `XorShift32.getRandomInt()` と `nextInt()` をこの仕様へ寄せた。
以前のPythonエンジンはJavaScript検証統合に伴い廃止した。
`tower_runtime.js` は単一のAPIで範囲乱数を消費し、乱数キーの符号化順も明示した。

**重要な検証境界:** 乱数を消費する *回数* の基礎ルールと、
予約段階／実行段階の切り分けは修正したが、
全カード・全トリガーの RNG 呼び出し箇所が正確に一致した保証はない。
とくに間接呼び出しを含む `ExamCommandStack` の全CFGは未復元。

## 回帰テスト

- `tests/test_native_command_order.mjs`:
  - 2件の予約の `SpendCount` が最初の効果実行より前に完了すること
  - ネストした同フェーズ発動が消費済みの回数を見て再発動しないこと
  - コマンド条件のスナップショットが効果内のステータス変化で変わらないこと
  - 乱数は予約中には消費されず、効果実行順で消費されること
  - 実機から読める `GetRandomInt` の戻り値とゼロ幅範囲での更新
- `tests/test_contest_dfs.mjs`:
  - 移植したコンテストDFSの探索境界・同点優先順・評価式、共通JS XorShift32の固定ベクトル
- 既存JavaScriptテストとCI構文検査。

## 残る未検証事項

- `<ExecuteCommandImplAsync>d__111.MoveNext @ 0x80D91D8` の
  非同期state分岐／コマンドスタック挿入と実際の実行順序の全経路
- カードごとの `GetSearchCardList` の準備時・ExecuteEffect実行時の
  二重検索がすべてのMaster効果で必要かどうか
- 入れ子のコマンドと追加ドローを含めた36実機セッションの再検証
- 版一致、観測ログ取得境界、暫定カスタマイズ復元を含む比較条件

したがって本PRは **ネイティブの処理順序に対する確認済みの差分修正** であり、
シミュレーター全体が実機と完全一致したと判定したものではない。
